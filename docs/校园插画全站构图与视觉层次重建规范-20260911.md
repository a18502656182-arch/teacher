# 校园插画全站构图与视觉层次重建规范

状态：已确认的实施约束

日期：2026-09-11

适用范围：班主任工作台电脑端、手机端及其共用设计系统

## 1. 本轮任务的真实含义

这次不是在现有页面上继续换颜色、加插画、统一圆角或覆盖旧 CSS，而是以校园插画参考图为构图基准，重新建立工作台的页面骨架、信息层级、视觉重心和交互节奏，同时保留已经存在的真实业务能力、数据安全与保存规则。

参考图对**构图和视觉语言具有约束力**。旧资料中“参考图仅作方向参考”“不要求像素级接近”的表述，不能再被用来保留现有扁平后台布局。它们只在以下三类情况允许偏离：

1. 字体需要改用项目可稳定加载、中文可读性合格的字体；
2. 图标需要改用项目统一且可访问的图标系统；
3. 参考图中的错字、假数据、不可实现关系或明显生成瑕疵必须修正。

业务内容、真实数据量和长名单会影响内容密度，但不能成为构图偏离的理由。空数据也必须保持完整的页面层次，不能因为没有学生而把页面退化成大片空白和一排细按钮。

发生冲突时按以下顺序判断：用户最新明确要求 → 本规范 → `DESIGN.md` → 资料包中的旧视觉说明 → 历史 CSS。涉及认证、账户隔离、真实数据、保存确认、并发冲突和隐私的规则仍由现有业务文档与代码约束，不能为了视觉还原而削弱。

## 2. 目标用户、模式与成功标准

主要用户是每天高频处理班务的班主任，界面属于 **Operate 工作模式**：首要目标是快速定位、批量处理、确认保存和继续下一项任务。插画负责建立校园品牌与空间层次，不能遮挡高频工作。

每个页面必须在进入后 5 秒内回答四件事：

- 当前班级和当前工作区域是什么；
- 页面解决什么任务；
- 今天最需要处理什么；
- 下一步主操作在哪里。

视觉完成的判断不以“功能都还在”或“自动布局检查通过”为准，而以以下结果为准：

- 在基准视口中，页面区域比例、视觉重心、标题层级、插画体量和主操作位置与对应参考图明显同源；
- 真实 30–50 人班级和 100 人长名单仍能搜索、筛选、批量处理、分页或虚拟滚动；
- 手机端使用针对手机任务重新编排的界面，不是桌面页缩小；
- 每个主要工作面只有一个视觉上最强的主操作；
- 新用户看到的是校园班务产品，而不是通用 SaaS 后台套上蓝绿色主题。

- 为了和图一致删除已存在的搜索、筛选、批量操作、分页、备份、冲突处理和只读能力；
- 复制参考图里的错字、乱码、含混图标或不可点击装饰。

## 4. 新的桌面全局构图

### 4.1 全局顶栏

恢复参考图中清楚可见的横向顶栏，建议高度 64–72px。顶栏承载：

- 产品标识；
- 当前班级切换；
- 一级工作域，如“班级教学”“家庭学习”；
- 真实保存状态；
- 账户入口。

同一信息不能在顶栏和侧栏重复出现。保存状态只能反映服务器确认结果，不能用纯前端动画假装成功。

### 4.2 左侧导航

桌面侧栏建议宽度 232–248px。19 个模块必须保留，但不能继续以同等权重一次铺满。使用四个任务组和清楚的组标题：

- 今日：首页、作业、听写、考勤；
- 学生：学生名单、成长记录、积分评价、健康与照护、家校沟通；
- 教学：成绩分析、考试反思、课程日程、课堂工具；
- 班级：座位分组、值日岗位、班干部、积分规则、班级周报、期末评语。

高频入口保持展开，低频组可折叠或放入“更多”。当前模块使用明显但克制的彩色底、图标和文字权重表达。侧栏底部可有一处校园插画或账户/备份辅助区，但不能让工具入口与业务导航竞争。

### 4.3 主内容区

桌面内容区使用 24–32px 外边距。每页先建立“页面上下文 → 关键摘要/插画 → 工作区”的顺序，避免标题下面直接堆按钮和表格。

页面不默认由一组同样大小的白卡片组成。相关内容应合并为一个完整工作面，通过背景色块、分隔线、留白和排版建立层级。持续性任务优先放在页面内完成，弹窗只用于短确认、短表单和危险操作。

## 5. 新的手机全局构图

手机端在 390px 和 360px CSS 视口下单独设计，并以 `C5`、`C6` 为视觉基准：

- 顶部 52–60px，保留返回/页面标题、班级上下文和必要状态；
- 大插画只出现在首页或确有导航价值的页面，业务详情页使用紧凑情境插画或不使用；
- 主内容保持单列，列表与详情采用“先列表、后详情”或底部抽屉，不横向挤压桌面双栏；
- 底部导航只保留首页、学生、作业、成绩四个高频入口，其余从“更多/工作台”进入；
- 固定底部主操作必须适配键盘与安全区，使用 `100dvh`，不可遮挡最后一项内容；
- 批量操作仅在产生选择后出现，避免首屏同时显示所有按钮。

## 6. 视觉系统

### 6.1 色彩角色

- 画布：暖白或极浅米色，避免纯白铺满；
- 主色：天空蓝，用于当前状态和主操作；
- 学习/完成：粉笔绿；
- 提醒/待办：温暖黄色；
- 风险/逾期：低饱和珊瑚红；
- 主文字：深海军蓝，正文使用蓝灰；
- 分隔：低对比蓝灰线。

颜色必须表达语义，不能按组件随机换色。玻璃拟态主题仍然只保留架构接口，本阶段不显示切换入口、不混入高光玻璃材质。

### 6.2 排版

- 页面标题形成 28–36px 的明确层级；
- 区块标题建议 18–22px；
- 主要数据可到 24–32px；
- 正文 14–16px；
- 辅助信息原则上不低于 12px；
- 中文正文使用高可读系统字体或项目稳定字体，不依赖无法保证加载的网络字体。

大标题只用于页面身份或核心数据。按钮、筛选和状态文本使用中等权重，避免整页都是粗体。

### 6.3 表面、线条与投影

- 顶层工作面允许 16–24px 圆角；
- 输入、按钮和小型状态控件使用 8–12px 圆角；
- 避免每个内部元素再套一层卡片；
- 投影只用于浮层、当前选择或明确抬升的工作区，普通分组用色块和分隔线；
- 禁止继续追加大段覆盖 CSS 来压住旧结构，迁移页面应删除对旧结构的依赖。

### 6.4 插画和图标

现有 5 个插画槽位不足以支撑 19 个模块。建立按页面族与语义命名的插画注册表：主页场景、作业、听写、学生、考勤、成绩、成长、健康、沟通、日程、课堂、座位、值日、班干部、规则、周报、反思、评语，以及通用空态。允许同一页面族共用素材，不允许全部页面复用 `study-desk`。

首页插画应成为 240–360px 高的主要场景；业务页的情境插画可占页头 220–320px 宽、100–160px 高。图标统一使用一套 24–28px 的线面结合图标，不使用 emoji 作为正式导航图标。

## 7. 标杆页面构图

### 7.1 首页：以 C1 / C5 为主

桌面首屏由三段构成：

1. 顶部大幅校园场景，展示班级问候、日期/周次、最关键待办和一个主操作；
2. 今日任务区，按作业、听写、考勤、日程等真实待办排序；
3. 班级概览与本周节奏，用紧凑统计、时间线或列表承载。

手机首页沿用同一信息顺序，但改成纵向，不把桌面卡片机械缩小。正式空白工作区仍保留场景、页面说明和清楚的第一步，不生成假学生或假数据。

### 7.2 作业：以 C4 为主

桌面必须改为主从布局：左侧 320–360px 是可搜索、可筛选、可分页的作业任务列表；右侧是当前任务摘要和学生状态列表。页面顶部只保留一个主操作“新增作业”。

右侧学生区保留搜索、状态筛选、选择、批量处理和分页。当前无需使用的月份、学科、时间范围、高级跟进等条件进入筛选抽屉；批量按钮在选中学生后出现。编辑/删除任务放到当前任务的上下文菜单，不能和主操作同权并排。

移动端先显示任务列表，进入任务后显示学生状态；编辑器使用全屏页或底部面板，保存操作固定在安全区上方。

### 7.3 学生：以 C3 为主

桌面使用左侧名单、右侧学生详情的主从布局。左侧支持姓名/学号/小组搜索和分页；右侧先展示身份摘要，再展示作业、听写、考勤、成长与沟通的近期时间线，编辑资料作为次操作。

健康与照护的敏感字段只在相应权限与明确入口中出现，不能在普通名单中成为公开标签。手机端从名单进入单学生档案，不在一屏挤入全部指标。

### 7.4 听写：以 C2 / C6 为主

桌面按“任务与材料 → 学生 → 当前批改”形成清楚的三段式工作区。批改区只突出当前学生、当前词表、错误选择和“确认保存并下一位”。保存失败、409 冲突、未保存草稿、请假/未参加和全对确认继续沿用现有严谨逻辑。

手机端一次只处理一个学生。页头显示任务和进度，词条成为主要内容，底部固定“确认并下一位”。没有点击错词不能自动推断为全对，必须明确确认。

## 8. 其余页面按任务族迁移

| 页面 | 页面族 | 推荐结构 |
|---|---|---|
| 考勤与请假 | 名单处理 | 摘要 + 日期/状态筛选 + 学生名单；选中后出现批量状态条 |
| 成绩分析 | 数据工作台 | 考试列表 + 录入/趋势/分析详情；数据图与录入表分层 |
| 积分评价、成长记录 | 学生跟进 | 学生/事件列表 + 详情时间线；新增记录为唯一主操作 |
| 健康与照护、家校沟通 | 私密记录 | 学生列表 + 受限详情；清楚显示隐私与保存状态 |
| 课程日程 | 计划器 | 周课表/个人日程分视图，避免卡片墙 |
| 课堂工具 | 专注工具 | 先选点名/分组工具，再进入沉浸式结果区 |
| 座位分组 | 空间画布 | 工具条 + 教室座位画布 + 当前选择信息区 |
| 值日岗位、班干部 | 责任编排 | 周期/岗位列表 + 人员与职责详情 |
| 积分规则 | 规则库 | 规则列表 + 规则编辑区；历史事件不受规则编辑影响 |
| 班级周报、期末评语 | 内容生产 | 历史列表 + 编辑/预览工作区；AI 草稿必须经过教师确认 |
| 考试反思 | 逐生流程 | 学生/考试列表 + 问题—原因—行动—教师备注步骤 |

账户、入口和管理员页面共用字体、颜色、控件和状态语言，但根据自身任务保持更紧凑的管理布局；不要求每个管理页都加入大插画。

## 9. 数据和状态压力测试

每个标杆页面至少覆盖以下状态：

- 0 人正式空白工作区；
- 30–50 人常规班级；
- 100–105 人长名单；
- 0、3、30+ 条任务或记录；
- 超长姓名、任务标题、备注和班级名；
- 保存中、成功、失败、离线草稿、409 冲突、只读和权限失效；
- 360、390、768、1280、1440 CSS 宽度；
- 浏览器缩放、软键盘和底部安全区。

正式工作区不得为了截图效果注入演示数据。视觉 QA 可以使用隔离的合成数据，但截图和报告必须明确标识测试环境。

## 10. 实施方式

### 阶段 0：建立可比较基线

- 记录 19 个路由/模块的现状截图与状态；
- 建立“模块 → 页面族 → 主参考图 → 特殊业务约束”映射；
- 固定 1536×1024 和手机参考比例的对照截图流程；
- 明确哪些旧 CSS 和旧组件会随迁移删除。

### 阶段 1：重建共享壳层

建立桌面顶栏、分组侧栏、手机页头、手机底部导航、统一保存状态和响应式内容容器。完成后再迁移业务页，避免每页各造一套导航。

### 阶段 2：完成四个标杆页面

先完成首页、作业、学生、听写的桌面与手机构图。它们分别覆盖场景首页、主从列表、学生档案和专注批改四类核心模式。每个页面都要用参考图并排检查；若结构和视觉重心仍不像参考图，继续调整，不能只说明“功能复杂所以不同”。

### 阶段 3：迁移其余 15 个模块

按第 8 节的页面族复用布局原语，不复制业务状态树。迁移一个页面，就从该页面 DOM 和 CSS 中移除已废弃的旧结构，不继续让 `workbench-repair.css` 承担无止境覆盖。

### 阶段 4：入口、账户与管理员适配

统一控件、字体、状态和品牌，但保留管理任务所需的信息密度。

## 11. 视觉验收门槛

自动测试通过只说明页面没有明显功能和溢出错误，不能证明达到参考图。每个阶段都必须同时满足：

1. 在 1536×1024 对应桌面参考图、390px 和 360px 手机视口分别截图；
2. 参考图与实现图以相同显示尺寸并排，不使用缩得很小的整页缩略图；
3. 检查区域比例、视觉焦点、标题梯度、插画体量、主操作位置、导航密度、控件高度、色彩面积和空白节奏；
4. 至少进行两轮“截图 → 发现差异 → 修正 → 重截图”；
5. 再运行 TypeScript、ESLint、生产构建、业务测试与 `qa:strict`；
6. 报告中分别写清视觉通过、功能通过、未覆盖状态和是否部署。

以下任一情况都不能宣称完成：

- 只是替换颜色、字体、圆角或插画；
- 仍然使用当前无顶栏、19 项等权侧栏、标题后直接表格的整体结构；
- 所有模块仍复用一张小型书桌插画；
- 只提供 1440/390 的无溢出报告，没有和 C1–C6 对照；
- 主要视觉仍由新增的覆盖 CSS 实现，旧 DOM 与旧规则完整保留；
- 只完成标杆页面，却把“全站完成”写入状态或变更日志。

## 12. 禁止项与边界

- 不做仅换肤式改版；
- 不把所有信息做成同样大小的卡片网格；
