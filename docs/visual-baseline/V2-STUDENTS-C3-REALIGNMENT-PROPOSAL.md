# V2 学生名单：参考差距—调整方案

状态：等待用户确认方向，不含产品实现。绑定被否决产品：`399a5c48b538b4cab8177d2bccb82011671db763`。

设计方向：班主任高频名单页应像可扫读的学生档案台——名单与近期状态先获得注意力，粉笔绿详情成为明确的学生记录场；真实数据、保存/只读逻辑和手机现场路径保持不变。

## 参考差距与拟调整

| 参考差距 | 当前成因 | 调整方案 | 保留边界 |
| --- | --- | --- | --- |
| C3右侧从插画、身份到学习记录形成连续粉笔绿大色面；当前虽有350px右栏，但混色接近白，插画下方像另一列普通表单 | `.detail`将浅绿与白色工作面高比例混合；身份、事实和动态都直接落在同一近白底上 | 保留约350px列宽，改成连续、可辨但不刺眼的粉笔绿记录场；插画与身份区连成一个顶部焦点，事实/学习记录使用少量白色内页承载。绿色负责“当前学生上下文”，白色负责“可读记录”，不靠整栏加饱和度 | 不扩大到压缩名单，不拉高页面，不换成无依据新插画 |
| C3近期记录用金/绿/蓝/红/灰状态签形成扫读锚点；当前近期状态主要是12–13px灰色串文，且出现`:20`等残缺时间 | 记录来源、日期和处理状态被压成同一行；所有状态共用muted颜色 | 将“业务状态”提取为带文字的语义签：待订正/待跟进用暖色，完成/已归档用绿，处理中/请假用蓝，未知/无记录用中性；来源与可靠日期作为次行。同步修复不同日期格式的展示，无法确认时不伪造日期 | 颜色不单独承载含义；不改变保存数据和排序前先核对真实日期格式 |
| C3身份头像、姓名、学号/分组、学习记录和“进入成长档案”有明确三级关系；当前姓名24px后紧接四个小指标与13px时间线，“完整档案”缩成右上小文字，长姓名时还会断字 | 详情栏把所有事实压成等权紧凑块，主入口没有稳定动作区 | 使用现有学生首字头像与校园插画组成身份头：姓名为主、学号/小组/座位为辅；四项事实降为一行摘要；最近记录变成可扫读记录卡/时间线；“完整档案”成为栏底或记录段后的宽动作，不与长姓名抢宽 | 不编造C3里的标签页或记录，不隐藏当前已有事实与动作 |
| 当前59px独立概览带加上下间距，把工作区起点推到约316px、表头推到约431px；C3搜索约247px开始、表头约326px，名单在首屏占比明显更高 | 四项指标被做成全宽看板，重复强调男/女统计，视觉上先于名单任务 | 取消独立有边框概览带。总人数进入标题/名单计数；男/女/电话维护保留为紧凑单行概况，置于标题说明或工具区辅助位置，不形成第二个主容器。搜索、筛选、批量入口上移，首屏优先展示更多真实学生行 | 不删统计、不缩整页、不通过减少行数伪造密度；105人和零人仍验收 |
| 手机正常可编辑空态的“新增学生”青色按钮被灰色小字覆盖；同时壳层“学生名单”和页面内“学生名单”重复，占用纵向空间 | `.mobileHeader span`误命中共享Button内部label；页面标题层重复 | 给班名独立类，按钮文字继承主按钮的白色与字号，并核对正常/禁用对比；页面内标题改成“当前班级＋人数”的任务上下文，避免与壳层重复。搜索/分组、名单行、Drawer及底栏继续独立重排 | 不把桌面表格缩进手机；保留44px触控、Drawer、批量选择和只读差异 |

## 实施后的验收证据

若方向获批，本页一次完成后提交：C3/当前同尺寸桌面对照；390×844普通、105人、零人及可编辑新增按钮图；右栏身份—记录—档案入口局部图；近期状态全类型局部图；1057px中间断点；正常关闭Drawer后再选择学生并显示批量操作条的真实流程图。所有证据绑定同一新产品提交。
