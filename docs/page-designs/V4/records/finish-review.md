## 3. 可访问性与手机风险

主清单焦点样式、筛选aria-pressed、搜索label、状态文字和装饰图空alt在源码中可见；状态不单靠颜色传达。手机断点将页面按钮设为至少44px高，清单/通知分别10条/4条分页，减少百条长列表的页面负担。已看实图未发现重叠、断裂按钮文字或主要操作被遮挡。

非阻断 RF-01：手机元信息与详情动作12–13px，当前390图清晰但比较细小；保留到可访问性专项核验200%缩放和最窄支持宽度。源码存在焦点样式不等于完整键盘流程已测，特别是门户弹窗与多层选择器。

非阻断 RF-02：信封PNG约2.08MB（目录读取得到），实际显示仅190×118/106×78px；建议交付正式接入前压缩并提供合适分辨率，避免移动端为小辅助插画负担过大。当前隔离设计审核无需因此重建设计。

本审核未测量每一对前景/背景的WCAG对比值，不称对比度或读屏全面通过。

## 4. 功能与恢复风险

源码可确认：缺省record status统一为待跟进；搜索/状态/类型改变重置页码；自由时间和历史类型可继续输入；详情保留完整内容；通知复制明确不等于外发；正文摘要之外有完整通知入口。保存沟通采用旧对象与新结果合并，可保留reflectionId等旧字段；重试走已有pending而非再生成ID；sync有try/finally释放busy；dirty与beforeunload/导航事件有保护。只读入口及保存函数有双层限制。

非阻断 RF-03：390-save-failure.png里错误原因与“本机待同步”说明未出现在当前视口，源码把recovery放在长fieldset之后，失败首屏只见“重试同步”和禁用字段。建议在后置表单专项中将失败摘要放到固定footer附近或聚焦/滚动至role=alert；静态图不能证明读屏自动播报。重试按钮当前可见，故并非已证实不可恢复，不作为当前主页面阻断。

集成前必验 RF-04：真实save/update的时序、409导出/载入最新、切班、关闭再开、剪贴板异常、删除失败重试及读写权限必须通过交互证据闭环。当前源码的pending只存在React状态；“本机改动已保留”的持久性取决于宿主update实现，本审核没有读隔离宿主或真实workspace持久化，不可推断刷新后一定可恢复。原有8测试通过也不能独立证明新控制器这些路径。本项为正式接入门槛，不是已确认的隔离P01缺陷。
