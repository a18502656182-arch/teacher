# 家校沟通现场功能盘点

核对HEAD e21dda1的当前工作区；正式源未改。来源ClassroomApp.tsx:3237-3402 Records、837起MobileSecondaryPage及records分支1704起；NotificationDrafts.tsx；features/records/operations.ts、features/notifications/operations.ts；旧F-10/O-10/A-10是保留依据，不是重做清单或视觉批准。

| 功能 | 当前事实 | 设计位置与保留要求 |
|---|---|---|
| 记录归属 | classId优先，兼容studentId及历史姓名归属 | 当前班记录；同名/跨班/移除学生需验证 |
| 查询 | 类型、状态、姓名/内容/反馈/跟进/渠道；手机额外含日期/状态 | 紧凑工具栏与筛选，不能声称当前列表已支持学号 |
| 记录状态 | 待跟进/已跟进/已归档；未填状态显示待跟进但部分计数/筛选只算显式状态 | 清单分组与详情状态修改；缺省状态一致性列P01待核对 |
| 新增/编辑 | 学生、时间、类型、渠道、目的、家庭情况、沟通内容、家长反馈、跟进 | 学生和内容必需，其余原有规则保留；敏感家庭情况不铺满摘要 |
| 时间与类型 | 桌面时间自由文本，手机date输入；桌面6种类型，手机8种；桌面有家访渠道，手机没有 | 保留历史自由时间、类型/渠道，不因表单枚举丢失旧值；P01统一展示需实测 |
| 学生选择 | 桌面常用8人/20人分段、姓名学号搜索；手机共享搜索选择 | 百人可用、不整班select、不依赖小组 |
| 记录复制/删除 | 公共剪贴板反馈，复制载荷为学生/类型/content/followUp；共享危险确认 | 详情操作保留；取消删除不改变数据，不新增成长事实 |
| 通知对象 | 空数组为全班家长，可选多人；姓名/学号/小组搜索前20项 | 通知页独立对象选择，百人/多人/移除对象核对 |
| 通知草稿 | 标题/内容必填；渠道班级群/私聊/电话提醒；新建编辑删除 | 右侧通知区，手机单独标签，完整编辑后置专项 |
| 通知复制 | 复制标题+正文，成功后可标已复制，复制不外发 | 不使用“发送”按钮或成功发送状态 |
| 回执 | 手工记录老师已收到反馈；保存为空时旧操作写已确认知晓 | 保留receiptNote和历史；不捏造已收回执 |
| 保存 | update后await save，成功关闭、失败保留；只读禁写 | 隔离合成失败/409/重试与草稿保护必须验证 |

## 尚未修复的源码风险

- 记录与通知新增失败后重试可能再次生成ID；多个persist没有try/finally，抛错可能busy不释放。
- 沟通编辑可直接关闭/遮罩关闭，缺少明确脏草稿保护；通知脏关闭路径依赖恢复原值，回执已有文本也可能一直视为dirty。
- 桌面状态/删除失败的recordError主要显示在编辑器内，页面路径可能看不到错误；手机详情把ReactNode放入state，状态改变后展示是否同步需验证。
- 列表无分页；百人记录和通知的长内容需可达、不能删数据来缩短页面。
- 保存沟通的操作重建对象未保留reflectionId，而模型存在该关联字段；编辑反思产生的记录有丢关联风险。历史名称fallback/内容用“｜”分段也须测试，不能贸然重写原业务格式。
- 再复制已记录回执的通知会标为已复制，receiptNote仍保留；需明确呈现历史回执，不能把复制理解成发送或回执消失。
- followUp是文本，没有结构化跟进日期，不能从候选约定文案推导“逾期”统计或自动提醒。

以上是现场盘点和P01测试清单，未实施修复。正式workspace保存/冲突/权限待后续接入审核。

## 状态覆盖计划

本轮仅双端主状态现状与C01候选。后续P01需：全部/待跟进/已跟进/已归档、无结果/空班、旧缺省状态、100+与长记录；详情、新增编辑、全部历史类型/自由时间、学生选择、删除取消/确认；通知标签、草稿编辑、全班/多人、复制成败、回执含旧文本、只读、校验、保存失败/异常/409及导航草稿保护。弹窗未审与功能未测分开记录。
