# 成绩页功能与状态盘点

依据：当前ClassroomApp.tsx Scores/ScoresWithExam、MobileScores/MobileScoresWithExam；ScoreTrends.tsx；ScoreItemAnalysis.tsx；features/scores/operations.ts，以及旧实施包trackers的F-11、O-11条目（历史功能保留依据，非当前设计批准）。

| 功能 | 当前入口与保留要求 | P01须覆盖 |
|---|---|---|
| 考试管理 | 当前班考试库/新增编辑删除/科目/日期，库搜索科目年月排序分页 | 无考试、新科目空白、切换、草稿关闭、删除确认、失败恢复 |
| 录分台账 | 逐生/批量同分、总分、平均、重点、建议、反思关联；选人后显示批量动作 | 0与空白、部分录入、不同满分、105人、长科目、跨班拒绝、只读 |
| 筛选与规则 | 学生/学号、小组、显示科目、区间、重点、排序、满分与分段编辑 | 搜索空态、批量选择与筛选切换、满分变更 |
| 历次趋势 | 班级或学生、考试关键词、科目、最近12/24/全部、台账分页；图最多36场 | 无数据/单场/长期、不同满分、录入覆盖率；不能捏造走势 |
| 试卷与知识点 | 人工项目/逐生录分/删除；上传JPG PNG WEBP PDF<=12MB；AI候选人工核对确认 | 无项目、识别中/失败、待核对/已确认、重复确认幂等；隔离仅合成不调用真实AI |
| 保存 | 保留workspace/operations；本机应用后等服务器确认 | false/throw/409、关闭切换与选人状态、重试避免重复创建 |

源码风险（尚未修复）：studentScoreSummary用原始分平均及最低原分推导weakSubject，不同满分不可解释成标准化弱科。ScoreTrends的subject选择当前仅筛选含该科的考试，rate仍算该场所有已录科目，不可把图标为“该科得分率”。缺失点被linePath过滤后连线，间隔语义应审核。operations的setScoreEntries还会写回student.score，这是旧业务派生值，不能在档案中当长期评价；本轮不改此行为。旧分布按完整学生原分平均切90/80/60阈值，不能扩展成跨满分公平比较。

P01须明确这些口径与功能，不以视觉修改默默重写正式业务。候选暂不摆上述易误读平均/分布指标，分析与趋势入口仍保留，后续设计必须给出口径与真实状态。源码异步多处await save未try/finally，异常锁死/重试和脏关闭需核验。

实际恢复：4217/scores-source.html，只读合成数据，Vite仅内存追加导出；真实入口未修改。恢复截图只证明正常双端主视图，未运行全部功能验收。两端源码并非共享同一视图，正式接入以后应复用批准后的同一P01组件。

## P01实现补充（2026-09-15）

隔离ScoresDesign已覆盖考试编辑/删除/库、逐生/批量录分、查询分页、满分分段、建议与原有等级/关注科目、关联反思只读查看、趋势筛选与学生选择、人工分析项/录分/删除、合成候选核对确认。桌面输入先暂存，显式保存后使用原operations；待同步锁住重复写，false/throw重试只同步已应用改动。分析识别按钮只生成合成候选，不上传所选文件。

独立ScoreTrendsDesign复制原读模型，明确科目只筛包含该科的考试、每人至少一科计入学生覆盖、按日期排序场次等距，缺失点断线；没有更改正式ScoreTrends。未带入旧主页大统计区和默认推断性建议，原有建议/等级可在本次学生详情维护，原始平均可查看，不声明常态评价。正式业务派生student.score写回仍按原操作保留。趋势/分析独立视觉尚未获用户逐项审核，不能只凭主页面批准归为全D。


## 2026-09-15：主标签页必须单独展示设计并限定批准范围

成绩录入候选确认不能替代历次趋势、试卷与知识点的构图与关键状态确认。用户本轮指出遗漏，两个主标签页退回设计。弹窗可后补的授权不适用于主工作区。历史技术复核与截图保留，但不得覆盖最新否决。先独立双端候选，获方向确认后制作可运行稿并审核；有数据/空态均要展示，不能只靠切换合成fixture掩盖布局缺失。正式保存、草稿、冲突、operations不因视觉重做而改写。
