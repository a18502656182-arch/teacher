## 2. 忠实度结论

**有限范围可交用户审阅；不能写成无保留技术全通过或用户批准。** 已实现候选的核心信息结构：紧凑筛选、浅蓝趋势图与浅绿所选考试、下方连续台账；个人模式有姓名/学号、本人得分率、已录科目和逐科分数，班级模式有学生覆盖，未把班级人数指标换标题冒充个人指标。图中 9/05 缺录处断线；空态保留考试与“未录入”。源码使用 null 判别，零分仍进入统计及绘图。

试卷任务、候选核对、已确认分析项三者分离。手机平时不展开候选字段，进入核对才展开；桌面由“核对候选”进入受保护的 inline 编辑，保留原 controller 的 dirty/busy/pending/save 语义。这是对候选直接可编辑表格的合理实现调整。既有真共享壳层与顶部考试操作保留，候选虚构导航、账号及科目切换未照搬。

忠实度不等于像素一致：实际桌面页头较高，1536 趋势首屏仅露出首条台账，而候选可见六条；手机班级趋势增加所选考试详情，台账下移；实际手机台账及分析项分多行，密度比候选低。它们未删功能，但增大滚动成本，应随实际图明确交用户判断，不能称完全复刻。

执行者另询问 P01 曾有“较前一有录场次数值变化”而 P02 未保留：六张本轮候选没有把数值差作为必备指标，C03 以个人曲线、所选考试、覆盖和台账为核心，因此本报告不把缺少 delta 判为 C03 忠实度失败。是否需保留为低强调明细属于功能盘点待定项，不能擅自恢复成进步/退步 KPI；若补回，应同时给比较场次与录入范围说明。

## 4. 功能与无障碍风险

源码可支持以下结论：台账选中 id 驱动考试详情和图点强调，“查看本次录分”通过 guard 再 switchExam/switchTab；科目过滤明确只筛包含该科的考试，图仍按本场已录科目，文案对此有说明。历史日期排序且场次等距，最多绘制手机 6/桌面 36 场，其余在分页台账中保留。每人得分率先取整再求班级平均会有舍入误差，且样本/科目覆盖变化影响跨次比较；页面已给范围警告，不应据此作学生能力提升结论。

候选仅存于 paperAnalyses，已确认统计来自 knowledgeItems；`saveEditor` 的 paper 分支校验名称和正满分后才调用 confirmScorePaperAnalysis。该 operation 对已确认状态幂等并按 id 去重。失败后 pending 重试调用 sync，不重新新增。编辑取消/切换沿用 guard。上述为代码检查，不替代真实保存、冲突与导航测试。

输入有 label、筛选展开/选择状态有 ARIA、图有文本替代入口，零分和缺录用文字区分。尚未完成计算样式对比度、hover/focus、Tab 顺序、读屏、文本放大、软键盘、真实触控目标及多主题验证。CSS 手机按钮基线 min-height 为 42px，不能宣称全部满足 44px 舒适触控建议。长候选核对表同样未限长；核对编辑本身允许长内容，但需后续验证错误提示与保存动作在长表中的可发现性。
