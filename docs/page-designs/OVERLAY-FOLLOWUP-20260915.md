# 弹窗与未覆盖内容补审

## 用户授权与批准边界

2026-09-15用户指出成长摘要/新增弹窗仍有旧样式，之前审核页面也存在类似情况，问能否后置。助手明确可以继续其它主页面设计，但弹窗/未覆盖内容必须正式接入前补审；随后用户“可以 继续下一个页面”。本次只接受成长P01主页面范围，并授权下一页健康与照护候选，不构成成长整页D、V3整批D/R或上线批准。

学生、作业、考勤已有批准历史原文保留；新增弹窗补审条件，不能将原主页面批准扩大到新补弹窗或未展示内容。成长指标GROWTH-PERIOD-METRICS另行保留。

## 待盘点与补设计

| 页面 | 待补审核范围 | 状态 |
|---|---|---|
| 学生 | 新增/编辑、导入/替换/删除、批量、完整档案内层 | 待逐项核对，不宣称全部旧样式 |
| 作业 | 任务编辑、学生详情、批量及删除确认等浮层 | 待逐项核对 |
| 考勤 | 月历、筛选与确认/失败恢复浮层 | 待逐项核对 |
| 成长 | 摘要、新增、全文、脏关闭、冲突确认；指标/摘要口径 | 已见用户截图，视觉重设计未完成 |
| 照护 | 新增/编辑、共享学生选择、删除/脏关闭、冲突恢复确认；必要信息与完整键盘巡检 | 用户再次指出弹窗问题，主页面认可；浮层视觉仍待补审 |
| 后续页 | 各自inventory列出的详情、编辑、选择、确认、空/失败等 | 每页记录覆盖与缺项 |

合理顺序：继续逐页主界面候选及隔离实现 → 集中补齐浮层与未展示状态 → 人工补审 → 本批D条件齐备 → 接入与R。共享弹窗外壳调整要回归受影响已认可页面。保存丢失、关闭卡死、冲突无法恢复等功能阻断不能以视觉延期掩盖。

隔离稿可以展示合成状态，不能以“隔离”为理由永久省略；跨页真实数据、服务器权限/保存/冲突另在接入阶段验证。未展示、未测、未批准必须分别记录。

脚本兼容：record.overlayReview.requiredBeforeIntegration为true时，未有当前prototype.commit对应的人工补审source/approvedAt/approved，integration与result-review阶段阻止放行；design-review阶段不受此项阻断。现有D历史保留。测试9/9通过。
