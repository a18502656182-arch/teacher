# 长期决策记录

## 2026-09-12：迁移中的批改逻辑共用与接线门槛

先将已有批改状态、草稿、重试及服务器确认后切人的逻辑原样抽取，再让旧视图和新视图共用。独立UI探针必须标明模拟，不访问工作区API。CSS Modules不能自动抵御旧全局CSS；完成隔离和真实保存验证前不切生产入口。插画使用主题语义角色，缺少玻璃资源时不冒用校园插画；当前原创PNG为candidate，资源压缩仍待上线门槛。

## 2026-09-12：新组件基准使用独立本地入口

- tools/ui-preview使用现有Vite/React依赖，只监听127.0.0.1，无API代理/数据库/生产路由和旧CSS。独立基准只证明控件自身，接入前仍必须验证新旧混合环境与真实保存契约。
- 原生Dialog作为候选公共浮层，关闭意图统一交controller，native top layer负责基础inert/焦点；接入旧页面时必须排除旧全局DialogAccessibility重复处理，同一浮层不能有两套管理器。
- 公共SVG注册表在新旧世代共用；旧名字映射只供迁移兼容，最终页面不使用旧结构类。玻璃切换仅在本地工具，新页面默认校园。

## 2026-09-12：允许重建全部展示层，旧UI兼容必须有退出终点

- 用户明确接受保留所有业务逻辑和功能、清除重构UI/DOM/CSS以适配校园及未来玻璃。仅换色/加图/保留所有旧结构不满足要求。
- 保持当前API、数据归属、保存/草稿/409、听写快照和备份契约；先盘点两端操作，再抽取controller与展示层。
- 未迁移页面可短期隔离使用旧CSS，迁移页必须无旧依赖；最终移除workbench-repair.css与homework-bootstrap-shell。旧文件体积本身不是删逻辑理由。
- C2三段式是任务材料、当前学生、批改的信息关系，不强制三条全高竖列；默认中央任务情境+批改、右学生队列，材料细节可展开，避免挤压词区。
- 未来glass保留theme/token/artwork/material降级接口，仅内部验证；首版不公开切换，不复制业务树，不改变草稿和备份版本。
- 详细执行唯一入口为项目实施包00。资料包制作时仅完成计划资料，不代表实施已完成；代表页视觉门槛通过后再全面铺开。

本文记录会约束后续实现的长期决定。新决定追加日期、背景、选择、原因和代价；不要把临时修复或纯样式调整写成架构决策。

## 2026-09-12：主题通过语义槽接入同一业务树

- 校园主题使用 `ThemeArtwork` 语义槽和共享 SVG 图标，页面选择 dashboard、roster、homework、assessment、planning 等业务语义，不直接绑定某一张参考图或复制两套页面。
- 桌面与手机可以使用不同壳层和交互布局，但读取同一份工作区数据、调用同一保存与冲突处理流程；响应式差异不能产生两套学生、任务或听写结果。
- 浅蓝紫玻璃主题保持 `planned` 配置和空素材映射，不显示切换入口。只有素材、组件状态和全站代表页面完成后才能对用户开放。
- 未迁移模块可暂时保留 `homework-bootstrap-shell` 兼容作用域以维持稳定布局；每次迁移一个页面族时删除对应旧依赖并补充浏览器回归，不能以一次性删除旧选择器换取表面上的文件整洁。

## 2026-09-11：校园参考图成为构图验收基准

- 用户明确要求按 C1–C6 完整重建页面构图和视觉层次；参考图对全局壳层、页面区域比例、视觉重心、插画体量、主从布局和操作优先级具有约束力。
- 允许偏离的范围限于稳定字体、统一图标和参考图中的错字/假数据/生成瑕疵；真实业务数据与长名单必须适配进目标构图，不能据此保留原有后台模板布局。
- 桌面和手机共用业务数据与状态，允许使用不同交互外壳；19 个模块继续存在，但导航按任务组和频率分层。
- 视觉验收必须包含 C1–C6 同尺寸截图对照，自动布局和功能测试不能替代。完整规范见 `docs/校园插画全站构图与视觉层次重建规范-20260911.md`。
- 代价：需要重建共享壳层、标杆页面和页面族组件，并清理旧 DOM/CSS 依赖，工作量显著高于换肤；收益是后续模块可以在稳定的视觉和结构系统上扩展。

## 2026-09-11：共享控件与弹窗行为

- 桌面和手机首页、班级切换、通用学生选择与复制能力共用实现，主题样式按控件和页面族拆分，避免重复业务树。
- 工作台弹窗由共享管理器按激活顺序负责焦点、Tab/Escape、背景inert与恢复；入口和管理员页保留各自管理器，避免同一弹窗由两个管理器竞争焦点。
- 视觉验收区分初始页面、编辑状态、实际交互与自动布局检查，代表页通过不能替代全站通过。

## 2026-09-11：听写持久化与双主题边界

- 校园主题优先，共用业务树、页面结构、SVG和主题资源插槽；玻璃主题仅预留，不展示未完成入口。
- 听写数据作为工作区可选version:1扩展，沿用账户所有权、版本冲突与完整备份；导出备份版本2，仍接收版本1。
- 每个任务固定材料和参与者快照，确认结果存状态、错词索引、时间和备注；复听新建任务。家庭孩子使用独立context，不进入班级名册。
- 保留5MB边界，预检4.8MB；200次、每次50人20词的合成听写数据约1.43MiB。全工作区与长期存储仍受容量约束，归档不缩小数据。未来规模超过上限时应迁移增量记录，不能静默删除历史或单纯提高阈值。
- 听写必须收到服务器确认才更新正式结果和跳转；未批改、请假、未参加不作为错误或全对。自动报词、OCR、AI批改与外部消息不在此次默认范围。

## D-001：用仓库文档和 Git 作为跨对话项目记忆

- 日期：2026-09-11
- 决定：新对话按 `AGENTS.md` 固定顺序读取导航、状态、变更、部署和决策；每次修改后同步文档并在验证通过后提交推送。
- 原因：Codex 超长对话可能压缩或折叠显示，聊天界面不能作为唯一项目记录。
- 代价：每次任务增加少量文档和 Git 维护成本，但能保留可审计的代码差异和进度。

## D-002：Git 不存部署包、运行数据、密钥和对话日志

- 日期：2026-09-11
- 决定：压缩包、数据库、`.env.local`、真实班级数据、QA 报告和 Codex 恢复资料仅本地保存；Git 只记录包名、大小、哈希和验证状态。
- 原因：避免仓库膨胀、隐私泄露和把运行状态误当源码。
- 代价：部署包需要额外本地/服务器备份，不能只依赖 Git 恢复。

## D-003：正式工作区空白，演示数据只留在演示入口

- 日期：2026-08-25（历史重建）
- 决定：正式账号首次进入不生成虚构学生、成绩或健康资料；演示数据只用于只读演示工作台。
- 原因：防止老师误把示例当真实记录并保存。

## D-004：健康信息按最小必要行动提示管理

- 日期：2026-08-25（历史重建）
- 决定：产品名称使用“健康与照护”，仅记录日常安排所需提示，不展示诊断细节，不作为公开学生标签，也不替代学校医疗和应急流程。
- 原因：减少隐私暴露和标签化风险。

## D-005：长名单操作必须支持搜索、筛选、批量处理和状态清空

- 日期：2026-08-29 至 2026-09-06（历史重建）
- 决定：学生、作业、考勤等全班名单按 50 至 100 人规模设计；不能依赖长下拉框，批量状态操作完成后清空选择。
- 原因：符合真实班主任高频操作，降低误操作和重复取消选择的成本。

## D-006：值日教学日跟随课程日程配置

- 日期：2026-08-29（历史重建）
- 决定：值日岗位不固定为周一至周五，必须读取课程日程定义的一周教学日，支持六天或七天教学安排。
- 原因：避免两个页面维护互相冲突的星期配置。

## D-007：AI 结果必须经过教师确认

- 日期：2026-08-25（历史重建）
- 决定：试卷识别只生成候选题号、题型、知识点、分值和置信度；老师确认后才进入正式统计。AI 密钥和文件处理留在服务端。
- 原因：OCR/模型输出不具备天然准确性，不能直接形成学生评价或正式教学结论。

## D-008：桌面与手机共享业务数据，但允许不同交互外壳

- 日期：2026-08 至 2026-09（历史重建）
- 决定：电脑和手机功能能力同步，数据来源一致；布局可分别优化，但不能产生重复写入、不同字段或一端缺功能。
- 原因：两端使用场景不同，但业务事实必须一致。

## D-009：GitHub 作为持续项目记忆的主远端

- 日期：2026-09-11
- 决定：默认将当前分支推送到 `github`（`a18502656182-arch/teacher`）；旧内部 `origin` 只作历史保留。项目状态、变更、部署和长期决策与源码一起提交。
- 原因：内部远端没有可恢复的用户凭据，而本机 GitHub Credential Manager 已具备可用授权。独立 GitHub 仓库能在切换 Codex 对话后继续读取完整项目历史。
- 风险：该 GitHub 仓库当前为公开仓库，必须持续排除真实学生数据、数据库、密钥、部署包和对话恢复资料；如项目不希望公开，应由仓库所有者改为 Private。
