## 1. 技术与运行结构

- React 19 + Next.js 16 接口约定，使用 vinext/Vite 构建。
- 本地数据层使用 SQLite 与 Drizzle；默认数据库路径为 `data/classroom.db`，可由 `CLASSROOM_DB_PATH` 覆盖。
- 正式工作台入口为 `/w/[token]`；演示工作台为只读静态示例，正式用户工作台默认空白。
- 管理后台为 `/admin`；公开入口为 `/`；隐私说明为 `/privacy`。
- 工作区保存采用服务器版本号和本机草稿兜底，冲突时不应静默覆盖服务器新版本。
- AI 评语和试卷分析均走服务端 API。密钥不得进入客户端或 Git。

## 3. 当前功能边界

当前工作台包括：首页、学生名单、作业追踪、考勤与请假、成绩分析、积分评价、成长档案、健康与照护、家校沟通、考试反思、班级周报、期末评语、课程日程、课堂工具、座位分组、值日岗位、班干部和积分规则。

下列能力不能因为页面入口存在就描述为已完整上线：

- 真实试卷 OCR/大模型适配服务及正式配额、计费、失败重试策略；
- 请假和日程附件的独立存储、权限与删除策略；
- 日程提醒推送、跨班日程和完整调课记录；
- 字段级跨设备冲突合并；
- 完整续费、退款、订单和审计商业闭环；
- 所有不可逆管理员操作的生产数据验证。

## 4. 验证标准

普通前端改动至少运行：

```powershell
npx.cmd tsc --noEmit --pretty false --incremental false
npm.cmd run lint
npm.cmd run qa:layout
npm.cmd run qa:strict
npm.cmd run build
```

涉及认证、工作区保存、数据库或正式部署包时，额外运行：

```powershell
npm.cmd test
```

视觉结论必须有真实桌面和手机渲染证据，不能以编译通过代替。当前已知非阻断警告是 `ClassroomApp.tsx` 对应前端 chunk 超过 500KB，后续需拆分。

## 5. 数据、隐私和 Git 边界

- `.env.local`、服务器环境变量、真实数据库、班级资料、备份文件、对话日志和部署包不得提交。
- `.env.example` 只允许记录变量名、安全默认值和说明。
- `data/knowledge-items.json` 是旧提交中已存在的教师知识索引；不要把新的班级运行数据写入该文件。
- 演示数据只能用于演示入口；正式工作区不能自动生成虚构学生或健康记录。
- Git 提交必须对应真实改动，历史未提交阶段只能以基线和重建日志说明，不能伪造逐步提交。

## 6. 部署边界

历史记录中的服务器目录为 `/www/classroom`，进程名曾使用 `classroom-web`。每次部署前仍需在服务器核对实际目录、当前进程和备份路径；部署完成后记录包名、哈希、命令、进程状态、验证地址和结果。
