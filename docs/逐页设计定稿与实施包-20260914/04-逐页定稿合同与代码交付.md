# 每页定稿合同
每页必须交付下面整套，单张PNG或“与首页一致”不成立：
- brief.md：任务、完整文案、功能映射、布局次序、主要焦点、与参考不同之处及原因。
- candidates/：桌面、手机候选图及生成提示词/输入来源/版本。
- preview/README.md：可运行设计组件路径、启动命令、所有状态打开方式；组件在项目受控源码位置，不在此另复制一份漂移代码。
- geometry.json：主要区域x/y/width/height、标题/正文/控件字体、padding/gap、颜色、圆角、素材路径/尺寸/fit/焦点、断点；从实际定稿浏览器测量，不能填猜测数值。
- assets.json：使用文件、hash、用途、来源、裁切、字体及可分发条件；图像在本地持久保存。
- states.json：03所有状态的适用性、fixture及截图。
- record.json：设计与产品版本、阶段、批准来源、证据清单、未解决问题。
- screenshots/：真实设计稿、接入结果与局部差异，不只有生成图。

## 状态转换
not-started → inventory → concept-review → prototype → awaiting-design-approval → design-approved → integrating → awaiting-result-approval → result-approved。
用户否决回needs-design-changes或needs-integration-fix，批准记录留历史。监工/测试不能写用户批准。
共享视觉修改使受影响的当前批准失效并进入needs-regression-review；新设计改变外观需重新D，接入偏差修复后重新R。按VISUAL_BASELINE要求检查既有批准页。
版本绑定：designApproval指向设计commit＋图hash；resultApproval指向产品commit＋对应designCommit。后续文档提交不应让产品版本产生无意义变化。

## 设计边界与判断权
候选图经用户认可后，真实设计稿仍要用户认可。生成图转代码时偏离明显，不能以“代码限制”静默接受。
布局尺寸、字体、图片和色彩由每页定稿合同确定；公共token不能覆盖个别页面已批准构图。旧“表格优先/禁止面板”不得压制有用途的彩色分区。
不可通过空白等高、裁内容、缩页面来实现对齐。功能性不对称必须真实可读。共享组件只抽取已稳定重复部分，主体保持各页独立。
