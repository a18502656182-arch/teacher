# 独立子界面出图与覆盖检查

2026-09-15，依据用户指出“已保存反思界面没有做……类似这种卡片的不同页面都要分开作图，不要让我人工审核时再查”。

## 执行顺序

1. 从当前源码逐项走查页签、卡片入口、详情、对象切换和读写流程；记录入口、用途、适用桌面/手机、源码路径及hash。不能只数路由或导航页数。
2. 结构或任务不同的界面单列surface。卡片跳转的页面、独立记录库、阅读详情、班级/学生分析不能被主页面候选覆盖。桌面同屏、手机拆页时按实际工作界面分别登记。
3. 每个独立界面分别生成适用的桌面和手机候选，登记到record.candidates和surfaceCoverage.surfaces；禁止拿同一张图重复覆盖两个独立界面。空态、长文、草稿/已完成等变体也须列入状态合同；结构变化时另出图。
4. 提交方向审核前执行候选覆盖检查；执行者先核对入口盘点完整、亲自打开图片，再交用户。用户只判断设计，不负责替执行者查漏。
5. 候选经用户确认后制作可运行稿。同一字段/组件的编辑变体可以复用已批准实现，但须注明复用来源、返回路径和状态差异；独立阅读页不能用编辑表单替代。
6. 可运行审核前逐入口实际打开，记录各界面桌面/手机截图、fixture、viewport、hash及交互日志；执行prototype检查。用户批准范围只绑定明确证据。

## 机械检查

在项目根目录执行：

```powershell
node scripts/page-surface-design-audit.mjs --record docs/page-designs/V4/reflection/record.json --stage candidates
node scripts/page-surface-design-audit.mjs --record docs/page-designs/V4/reflection/record.json --stage prototype
```

候选检查核对已声明界面的图片存在、hash、桌面/手机覆盖、图片跨界面复用、源码是否变化。prototype另查候选是否获批及实际截图是否齐备。主工作流对带surfaceCoverage字段的记录执行同样检查；新模板必含此字段。

脚本不能证明未登记的入口不存在，也不能判断好看。源码走查、图片阅读、交互可达性检查仍是执行者责任，不能用脚本PASS替代。历史记录不批量伪造盘点；后续接续任何页面时先补inventory，再继续制作或提交审核。
