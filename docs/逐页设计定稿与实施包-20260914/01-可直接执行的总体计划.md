# 逐页定稿后接入：实施计划
## 验收目标
用户先看到每页完整外观与操作状态，明确批准后，执行者复用同一实现接入业务。生成图片是候选；只有经用户批准的真实可运行页面设计才是接入基线。
不承诺生成图与网页跨设备逐像素相同。固定环境/固定数据下，已批准设计实现与接入实现须保持几何、字号、颜色、插画和布局一致；技术限制必须在设计审核时解决或取得明确接受。

## A0 接续与盘点（当前先做）
1. 检查git status、HEAD、当前账本和未提交文件。保留他人修改；不重置、不混合提交、不复述旧任务。
2. 读取旧监工报告及用户否决原因作为问题证据，不继承其审美结论。
3. 从路由/组件/真实可用预览盘点本批每页的字段、按钮、tab、筛选、弹窗、Drawer、状态及数据来源。使用03的映射表；标明已验证、未验证、拟改位置。
4. 打开本批C1-C6相关图与实际截图，列出逐页缺口。无独立参考的页面必须设计独立稿，不用“沿用首页”结案。
5. 建立每页record.json；inventory只是待执行范围，不是另一份批准账本。
6. 按05迁移主账本/检查器到分阶段批准，保留历史；检查当前实现，已修复功能不重复做。

## A1 逐页候选设计（可改设计资料，不改正式业务接线）
输入：实际桌面/手机截图、逐字功能文案、状态清单、已有参考、素材清单、目标画布。
每页至少一份完整桌面候选和一份独立手机候选。通过ImageGen生成并实际看图：字段遗漏、重复按钮、中文错误、假数据、无法实现布局逐项记下。图片里的文字不是最终UI文字源。
学生名单先独立交用户确认方向；其它页可在同批一起展示。用户不满意则返工本页，不能进入代码阶段再凭感觉补。
对只修小状态的迭代可直接在已批准真实设计稿改，不必反复生成整页图；新增页面方向不能省略候选阶段。

## A2 每页制作真实可运行设计稿（允许写隔离视图代码）
目的：将视觉候选变成真实可测、可复用的页面设计。它是具体设计实施，不能把已有不好看的预览改名交差。
在同一项目建立开发专用隔离预览入口，优先复用已有QA/fixture机制。采用本项目React、字体、按钮和图片；新页面样式限定页面命名空间。预览不在生产导航暴露、不读写真实数据库或用户存储。
候选输出拆成独立插画资产与真实文字/控件；不能把整张图片铺上再叠透明按钮，不能把图中文字切片当UI。
复用实际controller的类型和read-model接口，使用合成fixtures与显式action adapter。只替换数据/动作适配器接线即可进入产品；避免另写一份静态HTML再重新猜着复制。
每页完整实现02/03要求的关键状态及手机重排；任何动作都指向真实既存能力或明确标为预览模拟，禁加无用装饰操作。
候选图→可运行稿：同屏对照，一批检查、集中修复、一次确认。重大差距未解决就保留待修，不能以有限检查轮数为由宣布通过。
登记所有素材、字体、尺寸、颜色、断点、裁切、完整文案、组件入口和预览版本。

## D 暂停：本批逐页设计定稿
展示本批每页的候选图、真实设计稿桌面/手机、关键状态联系表、可点击预览及剩余差异。用户逐页认可，明确记录设计版本或提交。
本批任何一页未批准，其余页可以继续完善隔离设计，但本批不得正式接入。用户可明确缩小本批范围后单独放行，执行者不可自行拆批。
“好看/可以按这个做”仅在上下文清楚对应具体展示版本时记录；模糊确认先核实对象。用户否决就返回本页A1/A2。
不把设计批准等同上线或集成批准。

## I 复用已批准设计接入业务
按页接入；保留workspace、operations、读写权限、保存确认、冲突处理和班级隔离。
函数签名可做窄适配，业务重构另列任务；不能为迁移方便重写controller、删字段或偷偷替换数据语义。
将设计组件直接用于产品入口，改动限数据和动作接线。移动版也用已批准实现。定稿后想改变布局/文案/操作位置，先更新设计版本重审。
每页绑定designCommit与productCommit，生成实际运行对照，更新主账本及记录。

## R 暂停：本批实际结果审核
同环境下比对已批准可运行设计截图与接入后的截图。固定视口、字体、数据、日期、主题、缩放和设备像素比；禁缩小实际图、替换参考图或忽略不利区域。
检查关键交互与空/长/失败状态，按AGENTS完成相称测试、构建和严格QA。提供产品commit、原始日志、差异解释与未测边界。
用户批准本批集成结果才能进入下批。可选监工只提供技术和差异报告，不给审美结论盖章。

确认生产不携带设计预览路由/合成fixtures，保留按需加载，删除只有本轮引入且已无消费者的临时内容。共享清理再跑已批准页面回归。
最终提交项目记忆与证据；部署仍单独授权。资料包本次不实施A0以后的代码任务。
