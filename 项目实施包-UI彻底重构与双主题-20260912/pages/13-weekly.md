# 班级周报：逐页执行卡

状态：`implemented`。模块 ID：`weekly`。源码相对 `app/w/[token]`：`ClassroomApp.tsx:Weekly/MobileSecondaryPage`、`features/weekly/operations.ts`。

参考：编辑工作区派生。页面应使用校园主题的连续工作区、明确的周次上下文和轻量教学插画；缺少专属参考图不允许回退成通用后台卡片墙。

## 已核实业务入口

- 桌面：概览、页内编辑、跨班周报库；13周选择、上一周/下一周、家长版/教师版、重新生成、标题/正文/下周行动、保存草稿、完成归档、搜索/班级/版本筛选、分页、预览、复制和继续编辑。
- 手机：本周概览与周报库；周次选择、关注学生、小组当前表现、成长记录、新建/编辑底部层、自动生成、复制、保存草稿与归档。
- 字段：`classId`、起止日期、版本、标题、正文、下周行动、状态、创建/更新时间、归档时间。
- 源码没有周报专用文件下载或打印。“导出”只存在完整工作区备份等其他模块，不能把资料卡种子写成当前周报能力。

## 本轮操作层收口

1. 新增共享周报操作，桌面和手机统一校验班级、真实日期、正文、原报告归属及同班同周同版本唯一性；同一报告更新保持稳定 ID 和创建时间。
2. 手机不再把每次保存强制归档，现明确提供“保存草稿”和“完成并归档”。只读和校验失败保留编辑器与输入，不再关闭后显示成功。
3. 旧备份中的无 `classId` 周报在载入标准化阶段归到当时活动班，此后列表严格按显式班级过滤。这是兼容选择，不是对旧报告真实班级的确定性推断。
4. 作业完成率只统计任务内实际存在的逐生状态，并同时保留预期人次数和未记录数；不再用学生当前作业汇总填补历史任务。
5. 积分、沟通/成长、考试和考勤只在有合法日期且落入所选周时进入周报依据。无日期旧记录保留在原业务模块，不归入任意周。
6. 考试跟进按各科满分换算得分率，真实零分计入，未录不计；不再用当前综合分判断历史某周。考勤只使用该周台账异常记录。
7. 优秀与其他正向名单由该周正向积分聚合，不生成“主动分享”等虚构原因；两组名单不重复。小组积分仍是当前累计值，页面已显式标为“当前”。
8. 手机操作区改为工具动作、次要保存动作和整行主归档动作；只读提示固定在保存动作上方，避免提示覆盖按钮或滚动后不可见。

## 成功与失败语义

- 草稿不写归档时间；完成才写 `archivedAt`。同班、同周、同版本再次保存更新原报告，不追加重复周报。
- 字段、日期、跨班、重复及只读失败不调用页面 `update`，当前输入保留。
- 普通工作区仍为本机乐观应用后进入全局保存队列。服务器失败、409 和重试由全局草稿/冲突处理；手机本机操作通过后已关闭底部层，尚不能恢复具体编辑位置。
- 复制只表示写入剪贴板，不表示发送到家长群。自动生成使用确定性本地汇总，不是 AI 内容。

## 浮层、长名单与当前浏览器证据

- 桌面编辑是页内工作区，关注、小组、成长和预览使用旧 `weekreport-modal`；手机编辑与详情使用 `MobileInfoSheet`。关闭、切周、切版本没有脏草稿确认。
- 10项纯操作测试覆盖两班各50人、家庭数据不变、草稿/归档、跨班与重复拒绝、旧无归属报告、作业缺失状态、日期积分、成长/沟通合并、正向聚合、不同满分考试及考勤。
- 本地 Chromium/CDP 覆盖 1440、1280、1057、768、390、360 六个宽度；自动打开编辑器、写入草稿并触发只读保存，检查两个长文本字段、提示、草稿保留及手机主操作整行宽度。
- 截图人工检查并修复手机双层粘性动作重叠、半宽主操作和底部 toast 覆盖。桌面仍是旧 `weekreport-*` DOM/CSS，本轮浏览器结果只证明业务回归和当前布局可操作，不是独立校园新页面验收。
