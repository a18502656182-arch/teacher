# 考试反思：逐页执行卡

状态：inventoried-with-gap。模块 ID：reflection。源码相对 `app/w/[token]`：`ClassroomApp.tsx:Reflection/ReflectionWithExam/MobileSecondaryPage`、`features/reflections/operations.ts`。

参考：教学分析派生。派生页面使用对应页面族构图和校园 token，不把缺少专属图解释为可回退旧 UI。

## 已核实业务入口

- 桌面：当前考试上下文、考试库搜索/科目/年份/月筛选及分页、学生搜索与分页、逐生查看成绩和跟进状态、填写五类反思内容、保存草稿、完成归档。
- 手机：当前考试切换、学生状态/已保存反思双视图、状态和关键词筛选、两类列表分页、详情/复制、逐生编辑与草稿/完成操作。
- 字段：当前班、考试、学生、日期、主要问题、原因分析、下一步行动、写给家长、班主任跟进、草稿/已完成状态。
- 完成反思会从该考试的重点跟进名单移除当前学生，并在家校沟通台账生成内部“考试反思”留痕；这不是外部发送。

## 本轮操作层收口

1. 桌面和手机改用同一 `saveExamReflection` 操作，统一校验当前班学生、当前班考试、原反思归属和必填主要问题。
2. 反思列表同时按 `classId`、学生与考试归属过滤；显式属于另一班的数据不会因学生 ID 命中而混入。旧无班级字段但能由当前学生和考试唯一归属的记录继续可读。
3. 草稿只更新反思，不删除重点跟进，也不生成沟通记录。完成后才移除当前学生的当前考试跟进。
4. 沟通台账新增可选 `reflectionId`。首次完成生成一条内部留痕，重复完成或编辑后再次完成会更新同一条，不再重复追加；旧无关联字段的历史留痕不做猜测合并或删除。
5. 当前反思不能改绑到其他学生或其他考试；旧无 `examId` 反思在教师首次编辑时可补到当前班考试。
6. 桌面和手机都明确区分完整总分、部分录入和完全未录入；不再把缺失科目显示为零分总分。
7. 班级切换后，手机考试筛选会回到新班有效考试。演示/只读点击保存会保留编辑器和输入内容，并显示未修改提示。

## 成功与失败语义

- 字段或归属校验失败不调用 `update`，编辑内容留在当前界面。
- 普通工作区保存仍是本机乐观应用，再进入全局保存队列；服务器失败由全局草稿、重试和冲突流程承接。手机在本机操作通过后会关闭编辑器，因此尚不能恢复到原来的具体浮层上下文。
- 完成只生成家校沟通内部留痕，不宣称通知家长或外部发送。
- 已完成记录重新保存为草稿时，不删除已经形成的历史沟通留痕；后续产品规则需决定是否允许状态回退或显示历史版本。
- 重复完成在 `reflectionId` 已建立后幂等。早期版本已生成但没有该字段的旧台账不会被模糊匹配，首次重新完成可能新增一条可追溯记录，原记录保留。

## 浮层与长名单

- 桌面编辑器当前嵌在主页面，考试库是旧 `score5-modal`；切换学生会直接替换未保存输入，没有脏状态确认。
- 手机详情和编辑使用 `MobileInfoSheet`；关闭、背景或从详情转编辑的焦点/草稿策略仍依赖旧公共浮层。成功本机更新后关闭，校验/只读失败时保留。
- 两端名单均分页，操作层已用两班各 50 人验证，但 100+ 名单搜索、长原因/行动、软键盘遮挡和嵌套焦点仍需随新视图实测。

## 当前浏览器证据

- 项目 Chrome DevTools 严格审计覆盖 1440、1280、1057、768、390、360 六个宽度，页面无横向溢出、按钮挤压、弹层长文本高度或运行时错误。
- 自动打开桌面/手机反思编辑器，输入合成草稿后在只读演示点击完成；五个长文本字段、只读提示和输入保留均通过。
- 截图确认页面仍是旧 `reflection5-*` 与 `MobileSecondaryPage` 构图，只能作为旧页面业务核验，不能算校园新页面或参考图视觉验收通过。
- 当前会话列出浏览器技能但没有暴露可调用的应用内浏览器控制工具，因此本轮使用仓库现有 Chromium/CDP 审计；没有检查正式账号数据或生产服务器。
