# 手机与弹窗逐项操作规范

## 手机壳层

1. 页头每个上下文只展示一次：班级、场景、保存。进入家庭后突出孩子，不重复班级名册入口。
2. 一级底栏固定五项，更多中完整显示其余模块；模块名称不能靠图标猜。
3. 详情有返回上一级。批改是专注任务；底部保存优先，可按统一壳层规则隐藏一级底栏并保留返回，但同族不得各造一套固定底部高度。
4. 固定元素高度由布局/测量变量统一，补env(safe-area-inset-bottom)。内容padding预留总高度，末行能滚到保存条上方。
5. 软键盘打开时输入不被覆盖，必要时保存条进入文档流；真实设备不可用时准确记录模拟检查范围。
6. 至少360×780、390×844、768×1024，短高/横屏补查。测试100%和200%缩放；文字不因容器固定高度截断。

## 弹窗账本

trackers/overlay-inventory.csv按模块给出种子，TASK-02必须展开到每个实际浮层。包括新增/编辑、选学生、批量操作、导入预检、删除确认、AI候选、账号、管理员电话/设备/续期等。入口/管理员若有不同焦点机制先记录后统一，不重复注册全局事件。

## 每个弹窗都按同一顺序验收

打开→首焦点→Tab循环→填写全部字段→校验失败→长文本→选人子层→关闭子层→父层仍可用→提交中→失败保留→成功→关闭后焦点恢复。
补查Escape、点击遮罩、右上关闭、底部取消四条路径。dirty时不能某条绕过离开保护；只读不能从键盘或子菜单触发写入。

## 表单与长数据

标签永远可见，不用placeholder代替。错误紧邻字段并关联aria-describedby；多行文本按内容滚动，不被单行控件高度覆盖。小枚举可select，100+学生必须搜索分页选人。选人初屏优先搜索/已选/近期，不能直接展示全班几百个按钮。
手机名单保留姓名、状态、必要元数据和一个主要入口；其他字段在详情完整提供。为好看而删字段/功能不允许。表格仅对确需横向比较的数据保留局部横滚，不能把所有页面外层overflow:hidden当修复。

## 保存与反馈文案

‘已保存’仅表示服务器已接受；‘本机草稿’不是‘已同步’。复制成功/失败使用lib/clipboard统一反馈。禁用按钮旁解释原因（未选学生/待核对/只读），不能只降低透明度让用户猜。
