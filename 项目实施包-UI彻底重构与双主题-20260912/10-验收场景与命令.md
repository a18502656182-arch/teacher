# 验收场景与命令

## 隔离夹具

E0正式空白；E1两班各50人；E2单班105人；E3家庭两个孩子；E4任务0/3/30条；E5听写8/12/60/200词含长词释义；E6长姓名、80字孩子名边界、长标题备注；E7只读；E8保存错误；E9并发409；E10旧备份；E11接近容量边界。
按当前schema生成，不把examples/fixture-spec.json当作可导入备份。不能复制正式DB来造测试，测试输出放临时目录或忽略的evidence-local。

## 独立验收维度

业务：字段与动作保全、权限、隔离、统计、保存/冲突/恢复。
视觉：C1–C6同尺寸并排、区域比例、插画、字阶、色彩面积、状态和操作可达。
响应式：溢出、遮挡、键盘、滚动、字体放大、聚焦与底部安全区。
架构：新页面不依赖旧CSS、controller单实例、主题替换不重挂载。
性能：构建chunk与初次加载、模块切换、105人搜索、200词编辑、接近上限保存的实际时间；记录设备/浏览器/数据规模，未建立基线前不承诺固定毫秒。

## 可运行的现有命令（项目根目录，PowerShell）

```powershell
npx.cmd tsc --noEmit --pretty false --incremental false
npm.cmd run lint
npm.cmd run qa:layout
npm.cmd run build
node --test tests/rendered-html.test.mjs tests/dictation.test.mjs
node tests/auth-flow.integration.mjs
npm.cmd run qa:strict
```

npm.cmd test已经串行包含build+上述业务测试+认证集成，避免同一代码无理由重复构建。当前qa:strict脚本支持QA_PAGES、QA_URL、QA_REPORT_DIR、QA_SCREENSHOT_DIR；使用前重新读scripts/layout-audit.mjs确认，不猜参数。
既有自动审计视口不含1536×1024；C图对照要额外实际渲染该尺寸，不能把1440图放大当同尺寸。
Node >=22.13.0；本地SQLite功能预览使用现有认证集成所示Next Node环境/独立临时DB。vinext Workers开发模式可能不支持node:sqlite，不能因预览写失败改生产数据库引擎。不要结束未知node进程；只停止自己建立且记录PID/端口的服务。

## 人工视觉报告格式

每页写：提交/视口/夹具/页面状态/参考图/实际截图/差异/修改/确认结果。每个维度pass或needs-fix，不能用总平均分掩盖主操作被挡、无插画、字太小等问题。
参考保留和业务纠错分别记录。至少完成一次发现差异与修复后的确认；未通过继续标needs-fix，报告工具不可用和未覆盖状态。

## 全站覆盖

19模块每页桌面+手机+主要编辑状态；家庭创建/切换/复习；词库/导入/历史/统计；公开入口、账户、管理员全部关键弹窗、隐私。trackers/acceptance.csv预置场景，不限于初始页。
自动断言不得只检查某段CSS文本包含一个值；优先真实可见行为、状态和位置。旧结构测试更新时保留原风险检查。

## 阻断完成

任何功能丢失、正式数据写入测试、混班、只读可写、失败跳人、冲突覆盖、旧CSS仍驱动迁移页、未展示的关键弹窗、参考构图未达标，都不能标done。500KB警告需解释和测量，不必为消警告修改稳定逻辑。
