# 旧CSS清除与回归控制

## 逐页删除步骤

1. 在tracker记录旧文件/符号/selector及消费者。源码搜索、CSSOM/开发者计算样式、真实DOM分别提供证据。
2. 新页面禁用旧CSS渲染，修复新组件缺失样式；再在混合迁移环境渲染，检查是否被旧全局污染。
3. 收敛旧样式作用域，保留未迁移页最小兼容，不向旧文件末尾加新主题规则。
4. 删除已无消费者的旧DOM；删除该页旧规则前核对手机/弹窗/打印/管理员是否共用。
5. 对共享选择器迁移全部消费者再删；不得强删导致非当前页损坏。
6. 更新布局审计读取文件与定位方式，不降低失败阈值；运行该族和受影响页面回归。
7. 最后删除旧样式导入与废弃文件，完成全站巡检。

## CSS写法

新页面CSS Modules+主题变量；全局允许根token和无障碍工具，禁止模块选择器散落global。只读/选中/错误使用稳定data-state或属性，不依赖nth-child决定状态。字体/颜色不在每页重定义。
禁止把整个旧CSS搬到新文件、改名后宣称清理；禁止新增一层[data-theme]选择器包住旧后台布局作为最终实现；禁止通过display:none留下第二套业务表单。

## Git与恢复

开始先git status并读diff，用户未提交修改禁止覆盖。每个可验证阶段小提交，含项目记忆。发现回归先最小修复；需要撤销已提交改动时审查git revert的范围，不能reset --hard或checkout --。不要把多个未通过页面混成一次‘全站完成’提交。
迁移开关仅开发过渡，公开页面最终只有一套；不能遗留可访问的旧UI路径并忘记验收。
