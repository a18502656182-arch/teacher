# 学生档案与关联删除核验

## 已核实入口

桌面Students和手机MobileStudents共用StudentProfile；桌面另有新增、替换/追加文本名单、批量编辑、逐生编辑、删除和CSV导出。手机有新增/编辑、追加文本名单、批量编辑、逐生删除。所有写操作仍通过根workspace的update建立本机草稿，弹窗内“保存档案”不代表服务器已确认。

StudentProfile字段包括住宿、最多8个标签、多位监护人、联系人电话/主要联系人/紧急顺序、照护类型/优先级/行动提示/注意事项，以及只读展示的听写和24条考勤历史。旧档案取消、背景点击和关闭按钮会直接放弃本次表单状态，没有脏关闭提示；这应在新浮层实施时修正，不能误写为已支持。

## 提取与缺陷修复

档案表单状态提到useStudentProfileController；字段校验和数据应用提到纯函数profile.ts。它同时更新当前students及目标rosterClass，替换目标学生的guardians/careProfiles，保留另一班和家庭听写数据。电话失败不产生新数据。

removeStudentRelations从ClassroomApp提到relations.ts。合成数据测试先复现两个原缺陷：删除一名学生会按同班examId删除同一考试其他学生的反思；听写任务全局filter会删除家庭、他班及原本为空的任务。修正后只删除目标学生反思，只在本次删除确实移除最后一名参与者时删除该班听写任务，其余空任务和其他场景原对象保留。

新增6项回归覆盖两班各50人、家庭两个孩子、目标/他班隔离、无效电话、空联系人、同一考试其他学生反思和跨场景空听写任务。没有连接生产数据库。

验证结果：生产构建、64/64自动测试、认证集成、TypeScript、完整ESLint和qa:strict通过；设计检测器对本轮变更目标返回0项。本轮没有改变视图结构，因此没有复用旧截图声称新页面视觉通过。
