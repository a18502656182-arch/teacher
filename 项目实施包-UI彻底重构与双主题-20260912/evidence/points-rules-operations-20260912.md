# 积分评价与规则库逐动作核验（2026-09-12）

## 源码事实

- 桌面积分入口在 `ClassroomApp.tsx:Points`；手机入口在 `MobileSecondaryPage` 的 `active === "points"` 分支。两端都有学生搜索/小组筛选/筛选结果全选、规则选择、自定义分值、执行人、备注、批量提交、排行榜或历史查看和撤销。
- 桌面规则入口在 `ClassroomApp.tsx:Rules`；手机入口在 `MobileSecondaryPage` 的 `active === "rules"` 分支。两端都有搜索、分类/状态筛选、新增、编辑、启停、复制和危险确认删除。
- 桌面记分原先不写 `PointEvent.classId`，两端撤销都直接按学生ID回滚。旧统计以当前班学生ID筛选，不能在显式 `classId` 冲突时优先采用事件归属。
- 桌面指标原文案是“本周”，实际没有日期过滤，统计了当前班全部历史。
- 规则数组原先以 `length` 判断是否使用默认规则。删除最后一条后空数组会再次回退默认规则，不能保留真实空规则库。
- 历史使用次数原先以 `includes` 模糊匹配场景、标题和理由；相似规则可能重复计数，编辑口径后也缺少稳定引用。

## 本次数据层修正

- 新建 `features/points/operations.ts`，桌面和手机统一使用当前班名单校验、事件快照、积分同步及撤销。新事件立即写 `classId` 和 `ruleId`；另一班、不存在学生、零分和不存在班级均不写入。
- 撤销只接受当前班事件；旧事件没有 `classId` 时继续按学生归属兼容。当前班 `students` 镜像和目标 `rosterClasses` 同步，其他班及家庭听写对象保持引用不变。
- 新建 `features/rules/catalog.ts` 和 `features/rules/operations.ts`。`pointRulesInitialized` 仅在首次规则修改后写入，旧备份的空数组仍加载默认目录，明确删除到空后则保留空库。
- 新积分事件使用 `ruleId` 统计引用；旧事件只按完整理由/标题快照兼容，不再使用任意子串模糊匹配。编辑、停用、删除规则不改历史事件快照。
- 桌面统计文案改为“累计加分/累计扣分”，与现有全部历史计算一致。没有伪造成周统计。

## 浮层与保存边界

- 手机积分有学生选择、规则选择、学生详情等 `MobileInfoSheet`；历史撤销在页面内。桌面学生与规则均为连续工作区，历史使用 `details` 展开区。
- 手机规则有详情和新增/编辑 `MobileInfoSheet`，删除复用全局危险确认；桌面新增及编辑为页面内区域，删除复用全局危险确认。
- 手机选择/编辑浮层直接关闭会放弃当前筛选或规则草稿，没有独立脏状态确认；主题与宽度变化下草稿保持尚未实测。
- 现有一般 `update` 仍是本地先应用、全局稍后保存。积分提交会立即清空选择和备注，规则保存会立即关闭编辑；若随后服务器保存失败，只能由全局本机草稿/重试承接，尚未达到“失败保留当前操作上下文、成功确认后清空”的TASK-05门槛。重复点击在保存确认前也没有操作级锁。
- 本次没有替换页面DOM或旧CSS，没有把纯操作回归写成视觉迁移完成。
