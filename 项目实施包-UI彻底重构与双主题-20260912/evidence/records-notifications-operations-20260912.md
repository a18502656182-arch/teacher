# 家校沟通与通知草稿操作核验（2026-09-12）

范围：F-10 / O-10。本记录基于当前源码逐个核对桌面 `Records`、手机 `MobileSecondaryPage(records)`、`NotificationDrafts` 以及成长时间线消费者。它只证明业务操作层与自动化结果，不证明新校园页面完成或线上已更新。

## 源码结论

- 桌面和手机原先各自拼装沟通记录，并用姓名查找学生。同班同名时会写到第一位匹配者；状态和删除只按记录ID全局更新，没有再次验证当前班。
- 新建沟通同时写 `records` 和一份 `source=家校沟通` 的 `growthEvidence`，而成长时间线又直接把 `records` 作为一类来源归集，因此同一沟通会出现两次。记录编辑/删除不会同步该副本，还会留下过期事实。
- 通知草稿数据类型允许多个 `recipientStudentIds`，旧编辑器却只有“全班或单人”状态。打开已有多人草稿时会映射为全班，保存后静默覆盖原对象。
- 通知复制只有剪贴板成功后才标记“已复制”，页面文案明确系统不自动外发；人工回执仅保存老师已收到的反馈。这两项口径保留。

## 已修改

- 新增 `features/records/operations.ts`：班级列表、学生归属、沟通新增/编辑、状态更新、删除和本机日期统一在纯操作层校验。
- 新增 `features/notifications/operations.ts`：班级草稿、多人对象去重/归属校验、新增/编辑、复制状态、回执、删除和本机日期统一处理。
- 两端沟通选人都保存稳定学生ID；编辑旧记录仍可用已有ID或当前班姓名兼容定位。新增记录不再额外写成长事实。
- `growthEvidenceForStudent` 与其他直接统计点排除旧 `source=家校沟通` 副本，沟通台账继续作为成长时间线的真实来源；没有删除旧备份字段。
- 通知对象列表支持多选和完成选择；编辑时保留多人数组以及原日期、创建时间、状态和回执。

## 自动化证据

新增8项测试覆盖：两班各50人和同名学生、当前班ID写入、编辑状态快照、空字段、跨班保存/状态/删除拒绝、旧记录兼容、多人通知保留/去重、跨班对象拒绝、复制/回执/删除隔离、本机日期。成长既有测试新增历史沟通副本去重断言。

聚焦测试通过15/15（其中新增8项、成长/健康既有7项）。完整生产构建、92/92自动化测试、认证集成、TypeScript、全量ESLint和 `qa:strict` 通过；构建仍有已知的前端chunk超过500KB警告。

## 未完成边界

- 生产页面仍是旧 `record3-*` 和手机布局，没有完成独立校园视图、CSS隔离或视觉验收。
- 普通工作区更新仍会在本机应用后关闭编辑器。服务器保存失败/409由全局草稿与冲突恢复处理，不能恢复单条编辑器上下文；本轮未虚构为提交后确认。
- 桌面记录无分页；编辑/通知/回执关闭没有脏保护；100+名单、长草稿、剪贴板失败、只读和嵌套焦点需随新页面在浏览器复验。
- `ExamReflection` 另有写入沟通记录的路径，仍使用旧即时写法和非标准日期，归入F-12处理，不能以F-10操作层测试替代。
