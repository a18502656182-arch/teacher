# 考勤逐动作与写入边界核验

## 当前真实能力

Attendance.tsx同时渲染桌面与手机，调用同一组handler。当前入口包括日期、月历回看、姓名/学号/小组/备注/状态搜索、小组与状态筛选、本页/当前筛选选择、逐生四态、逐生备注保存、批量状态/统一备注和一键全员正常；桌面每页50人，手机20人。页面没有业务浮层。

请假状态会写入默认事假、家长提交、待确认等兼容字段，也会保留既有请假详情，但当前页面没有填写请假类型、原因、联系人、确认、销假时间或连续日期的入口。历史文档提到这些能力不能覆盖当前源码证据，新视图不得虚构为已存在。

所有页面“保存”仍调用同步update，立即建立本机workspace草稿并清空选择/显示“已保存”；它没有等待服务器确认。若随后服务器保存失败，选择已经清空。这与本包“失败不清选择”的目标不符，必须依赖TASK05通用确认保存语义后再修正，不应在当前账本登记为通过。

## 修正与测试

日期生成从UTC toISOString截取改为本机年月日，避免中国时区凌晨显示前一天。考勤记录写入提到features/attendance/operations.ts，校验目标班学生，历史日期只写台账，当天才更新学生当前汇总。

一键全员正常现在只在老师实际输入备注草稿时覆盖备注；未编辑学生保留原记录备注。新增4项考勤回归及1项作业归属回归，覆盖本地日期、备注、历史日期、两班隔离和家庭数据不变。页面结构尚未迁移，浏览器视觉/失败态未验。

验证：生产构建、69/69自动测试、认证集成、TypeScript、完整ESLint和qa:strict通过。仍保留ClassroomApp及客户端chunk超过500KB的已知警告。
