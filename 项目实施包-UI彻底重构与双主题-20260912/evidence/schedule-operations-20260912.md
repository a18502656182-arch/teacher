# 课程日程与教师留痕操作核验（2026-09-12）

范围：F-15 / O-15。证据来自当前源码、纯操作测试、演示只读工作区和隔离的合成可写工作区；不证明独立校园日程页完成，也不证明线上更新。

## 源码结论与修改

- 桌面继续由 `ScheduleHub` 在“班级课表 / 我的日程与留痕”之间切换，手机继续在 `MobileSecondaryPage` 中使用同一工作区数据；两个场景没有复制第二套课程或个人日程数据。
- 新增 `features/schedule/operations.ts`，统一本机日期、月周范围、教学日/节次配置、周课表、班级活动、每日重点、个人事项与工作留痕的校验和写入。
- 周课表保存现在严格限制当前班与所选周，拒绝倒置学期、重复教学日、越界节次、周外活动/重点、重复或被其他周占用的 ID。保存当前周时会保留不在该周的旧活动与每日重点，不再因扁平化覆盖而静默丢失。
- 课程矩阵随教学日和节次数量规范化；同一班同一月周稳定更新。另一班、家庭孩子和其他工作区字段保持不变。
- 个人事项与工作留痕按显式班级过滤并兼容活动班内旧数据；关联学生必须属于当前班，支持多人且去重。时间倒置、无效日期/状态、跨班编辑和无效关联均被拒绝。
- “完成并留痕”同时更新事项状态和一条带稳定 `agendaId` 的内部工作记录；重复执行保持一条留痕。它只代表工作台内部记录，不宣称发送通知。
- 桌面与手机只读保存都会保留编辑器和输入。手机课程、活动、重点和配置在本机更新后继续保留编辑层并显示同步状态；活动日期改为真正的日期输入。月份默认优先当前学期内的本机月份，避免桌面和手机进入不同周。
- 手机四类编辑层和个人事项编辑器已记录打开时基线，关闭脏草稿前使用现有确认层。月和周在编辑期间禁用，避免把旧周草稿写入切换后的周；活动与重点编辑状态互斥。

## 本地浏览器证据

- 在演示只读工作区打开桌面和 390×844 手机课表，分别进入周课表、学期配置、课程、活动、每日重点和个人事项编辑。点击保存均显示对应只读提示，编辑器和输入保持；个人事项脏关闭能打开统一确认层，本轮没有确认丢弃。
- 在只使用合成账号和临时 SQLite 的本地可写工作区保存 6 天教学周、长课程名、班级活动、每日重点和个人事项；“完成并留痕”后只生成一条工作记录。刷新后所有结果仍存在。
- 同一合成工作区切到手机视图后默认进入当前月份，修改第二个教学日课程；桌面视图随后读取到同一变更，证明两端连接同一业务数据。浏览器控制台没有 error 或 warning。
- 倒置月份在纯操作测试中验证。受控月份输入通过浏览器自动填充时没有可靠触发 React 状态变化，因此不把它写成浏览器级通过。
