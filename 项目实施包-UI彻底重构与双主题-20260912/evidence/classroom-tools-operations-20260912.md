# 课堂工具操作核验（2026-09-12）

范围：F-16 / O-16。证据来自当前源码、纯操作测试、演示只读工作区和隔离合成可写工作区；不证明独立校园课堂工具页完成，也不证明线上更新。

## 源码结论与修改

- 原组件直接使用 UTC 字符串日期；本轮改为本机年月日，避免东八区凌晨把当天请假和分组记录归到前一天。
- 原点名本轮只存学生 ID，切班后可能把上一班 ID 当成新班已抽取，并按名册顺序显示却标为抽取次序。现在候选人与本轮状态都带当前班边界，展示保持实际抽取顺序，失效、请假和另一班 ID 会从本轮候选中移除。
- 请假人数只统计当前班名册内、当天且状态为“请假”的学生；另一班和已移除学生的旧考勤不再抬高计数。全员请假时点名和分组均不可执行，并显示真实空状态。
- 新增 `features/tools/operations.ts`，统一候选人、无重复点名、临时分组、班级历史和复制文本。分组数限制为2至12；人数少于请求组数时按可参与人数缩减，只生成非空组；105人分组不遗漏、不重复且人数差最多1。
- 分组记录写入显式 `classId`、本机日期、稳定学生 ID 和结果快照；记录 ID 冲突、无效班级/日期、人数不足均拒绝写入。另一班、积分和家庭数据保持不变。
- 课堂工具接收根层只读状态。随机点名是只在当前页面保留的临时结果；临时分组需要写工作区，只读时显示明确原因且不制造假历史。生成成功提示“正在同步”，不把本机更新描述成服务器已确认。
- 切班后点名、历史和提示都按班级隔离。历史复制按当时小组顺序输出；已移除学生只显示占位文字，不借另一班名册补名字。

## 本地浏览器证据

- 演示只读工作区在桌面连续抽取3名不同学生并成功重置；点击临时分组后显示只读原因且没有结果记录。390×844手机同样保留临时点名、阻止分组写入，页面无横向溢出。
- 隔离合成工作区包含甲班5人（1人当天请假）和乙班3人。甲班连续抽完4名可参与学生，顺序无重复且不含请假学生；请求6组时生成4个非空组，随后生成2组并能从历史打开第一次结果，复制文本与分组顺序一致。
- 切到乙班后，甲班本轮点名、历史和提示都不显示；手机端请求6组时生成3个非空组。把乙班3人全部设为请假并刷新后，显示排除3人，点名与生成分组按钮均禁用，已有历史仍可查看。
- 合成 SQLite 最终写入甲班2条、乙班1条分组记录；原积分条数保持1。桌面和手机控制台没有 error/warning，390px视口没有横向溢出。全部数据位于系统临时目录，没有使用正式账号或数据库。
