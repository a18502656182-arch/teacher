# 家庭学习完整迁移核验（2026-09-13）

范围：F-20 / O-20。实现提交：`872dee7`。证据来自当前源码、纯操作测试、只读演示工作区与系统临时目录中的隔离合成可写工作区；不代表线上部署或生产数据库验收。

## 审计发现与实现

- 原家庭场景与班级听写共用一层条件化标题、选择框和任务表格，家庭的“孩子切换→今日任务→错词/历史→孩子档案”关系不清楚；孩子档案新增/编辑也直接拼在大组件中，缺少独立校验和未保存离开保护。
- 新增 `FamilyScene.tsx`、`FamilyScene.module.css` 与 `features/family/operations.ts`。家庭页头、孩子切换、今日安排、个人错词入口和孩子档案使用独立校园构图；任务编辑、词库与批改继续复用同一套听写业务组件和数据，不复制班级/家庭业务树。
- 家庭任务只按 `context.kind=family` 和精确 `childId` 读取，每个任务只允许一个与孩子ID相同的参与者。重名孩子通过稳定ID保持各自任务、结果、错词和统计；班级学生和另一孩子不会混入。
- 孩子新增、编辑、归档和恢复经纯操作层清洗及校验。归档保留全部旧任务、材料快照和结果，但服务端校验拒绝为归档孩子新建任务；页面同时禁用新建、复听和批改入口。
- 今日任务使用当前本地日期，近30天统计只统计已确认并实际参与的结果。未批改不算全对，请假和未参加不计错误；已归档任务不再算作待处理人次，但历史仍保留。
- 任务编辑增加未保存离开保护。页面切场景、返回或关闭前会阻止丢失草稿；确认放弃后才返回。保存失败保留同一任务/孩子ID与字段，服务器确认后才进入批改页。
- 原创 `family-study.webp` 使用家庭学习物件构图，无人物、角色或文字；校园主题登记 `family` 语义槽，玻璃主题保持空资源映射且没有公开切换入口。

## 本地浏览器证据

- 桌面实测两个同名孩子分别显示三年级/一年级和各自历史；切换后任务、待批改和错词数量随ID变化，没有读取另一孩子或班级任务。
- 新增长姓名第三个孩子并由服务器确认保存；编辑后取消出现统一放弃确认，确认后临时姓名未写入。归档第二个同名孩子后，旧任务仍可查看，新建、复听和批改禁用；恢复后重新可用。
- 第一个孩子的个人错词只显示其已确认错误；点击“安排复习”建立新的待批改任务，原听写和原错词仍存在。第三个孩子使用自定义文本新建两词任务并完成逐词人工批改，页面收到服务器确认后显示已完成和个人错词。
- 任务编辑器填入名称与文本后尝试切到班级场景，被未保存保护拦截且字段保留；点击返回会先出现“放弃任务草稿”确认。
- 两个标签从同一revision打开：第一标签先保存批改，第二标签再保存孩子年级得到真实409。全局冲突条显示导出草稿与载入最新入口，孩子编辑器仍保留“并发草稿”，没有假报保存成功。
- 只读演示的家庭场景保持零孩子，不借用32名班级学生；新增孩子和写入入口禁用，空状态说明家庭与班级隔离。
- 390×844和360×800实际渲染家庭页头、三项手机动作、横向孩子切换、五个家庭子页、今日任务和固定批改保存栏。两种宽度均无整页横向溢出；横向切换容器保留触控滚动并隐藏原生滚动条。
