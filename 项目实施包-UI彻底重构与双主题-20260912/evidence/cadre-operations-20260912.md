# 班干部完整迁移核验（2026-09-12）

范围：F-19 / O-19。实现提交：`1ec62b6`。证据来自当前源码、纯操作测试、只读演示工作区与系统临时目录中的隔离合成可写工作区；不代表线上部署或生产数据库验收。

## 审计发现与实现

- 旧桌面与手机分别维护班干部界面和写入逻辑，小组长只靠岗位名称和学生当前小组推断，没有稳定岗位小组字段；岗位也缺少严格班级归属。正式空工作区在归一化时会被补入三条示例干部，造成假数据。
- 新增 `Cadres.tsx`、`Cadres.module.css` 与 `features/cadres/operations.ts`。桌面与手机共用当前班岗位列表、搜索、类型/状态筛选、详情、新增、编辑、删除和复制；旧 `cadre3-*` 与 `mobile-cadres-*` DOM 已从生产组件移除。
- `CadreRole.classId` 约束岗位归属，新增 `groupNumber` 保存小组长对应小组。小组编号只接受当前班学生实际使用的正整数并支持不连续组号；班委候选来自全班，小组长候选只来自目标组。删除学生和成长档案读取也按明确班级处理，不能因两个班出现相同学生ID误删或串读。
- 正式空工作区保持零岗位。班委允许先建立待任命空岗，小组长必须选当前班已有小组和该组学生；空任期保留为空并显示“未填写”，职责、状态、1至5分评价及小结都由同一操作层清洗和校验。
- 复制内容对待任命岗位写明“待任命”，不伪造已经任命某位学生。页面提交只提示“本机草稿正在同步”，服务器失败和409由共享工作区状态显示，未把本机更新冒充服务器确认。
- 页面使用独立班干部语义插画槽和原创透明水彩素材 `cadres-responsibility.webp`；玻璃主题素材映射仍为空且没有公开入口。

## 本地浏览器证据

- 正式空工作区首次打开显示0岗位，没有旧版三条示例岗位；纯操作空班测试也拒绝虚构小组长。
- 隔离可写工作区导入甲班105名学生和乙班50名学生。甲班建立一个长职责班委并从105人选择器搜索任命第105名学生，空任期保存后仍为空；另建立第27组组长，只显示该组候选。乙班建立待任命班委后切回甲班，岗位与学生均未串班。
- 修改编辑器后取消会先出现统一放弃确认，确认后原岗位名保持且临时名称没有写入。桌面只读演示中新增、编辑和删除禁用，查看与复制仍可用。
- 两个标签从同一revision打开：第一标签先保存，第二标签再新增岗位得到真实409；冲突提示、导出当前草稿和载入最新入口均出现。载入最新后第一标签更新保留，第二标签陈旧岗位消失。
- 临时停止本地服务后保存履职小结，页面显示“保存失败”、失败原因与重试入口，编辑后的内容仍在本机详情中，没有显示服务器已保存。恢复环境使用了不同的本地认证配置，故本轮不把随后一次重试记作成功证据；一般保存重试本身已有工作区自动化覆盖。
- 手机在390×844、360×800和768×900实际渲染。岗位列表点击后由详情替换列表工作区，编辑底栏完整可达；修正了手机壳900px与页面760px不一致导致768px无返回入口，以及360px标题被状态标签挤成孤字的问题。三种宽度均无整页横向溢出。

## 仍需后续处理

- `StudentLookupDialog` 仍是共享全局portal；本页已实测搜索和嵌套返回，但最终统一焦点回退、层级和主题隔离归TASK-08/09。
- 根CSS中的旧 `cadre3-*` / `mobile-cadres-*` 规则已经没有生产DOM消费者，仍需在TASK-30核对所有分组选择器后删除；本页通过不能解释为全站旧CSS已清零。
- 当前工作区一般编辑仍采用本机先应用、后台自动保存。岗位页没有“保存并下一位”流程；失败时保持当前详情并由全局状态重试，符合现有保存契约，但通用服务器确认式controller仍是后续任务。
- 物理手机、软键盘、弱网、线上真实账号与生产数据没有验收。没有生成部署包、连接生产数据库或操作服务器。
