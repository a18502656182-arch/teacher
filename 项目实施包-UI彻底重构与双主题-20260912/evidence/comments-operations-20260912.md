# 期末评语操作核验（2026-09-12）

## 源码确认

- 桌面入口仍是 `ClassroomApp.tsx:Comments`，手机入口仍在 `MobileSecondaryPage`。生产页面继续使用 `comment5-*` 和手机公共大组件，尚未达到独立校园视图及旧 CSS 退出门槛。
- 原实现的桌面学期选项、历史数量和保存查找直接读取全部 `termComments`；手机只按活动班学生 ID 过滤。显式属于另一班但学生 ID 异常重复的记录可能混入，桌面历史数量也会直接混入另一班。
- 原桌面和手机各自维护一份本地评语模板。模板会在没有记录时写入“参与班级活动”等表现，也会把缺少行动字段的考试反思描述成“已经形成改进计划”。
- 原桌面证据选择变化会重算模板并覆盖教师正在编辑的草稿；手机新建时直接写入本地模板。只读时手机仍关闭编辑器并提示已保存，桌面也会先显示同步成功文案。
- AI 接口返回的是草稿，保存才写入工作区；正式环境已有授权、工作区归属、配额与上游失败退款。原接口在学生名校验前扣减配额，且演示静态内容会呈现为学生事实。

## 本轮接线

- 新增 `features/comments/operations.ts`，统一当前班评语查询、原记录归属、学生归属、同学生/学期/语气唯一性、字段清理和稳定更新。
- 桌面与手机均调用同一保存操作；保存错误和只读操作保留当前内容。手机保存后继续留在编辑器，明确区分“本机草稿已更新、正在同步”和服务器最终结果。
- 本地生成只整理教师当前勾选的沟通、积分、考试反思与老师补充；无依据时保持空白并提示，不再根据学生当前汇总值或空缺记录补写表现。
- 证据勾选不再触发草稿重置。桌面学生/学期/语气切换和手机关闭增加未保存保护；手机语气切到无既有版本时保留当前内容。
- AI 请求不再默认发送未显式选择的当前成绩、积分和作业汇总。正式请求在扣配额前校验学生与依据；演示返回明确标注的流程示例，不再伪装为学生真实评语。正式只读工作区禁用 AI，演示静态流程仍可查看。

## 验证证据

- 8 项纯操作回归覆盖两班各 50 人、无班级旧评语、显式跨班错误、同键稳定更新、改绑/重复/空字段拒绝、家庭数据不变、无依据不编写及仅整理选中事实。
- TypeScript 和受影响文件 ESLint 通过。
- 本地 Chromium/CDP 在 1440×900、1280×900、1057×900、768×1024、390×844、360×780 六个宽度打开评语页；手机实际进入编辑器与二级依据浮层。自动输入后切换依据，草稿保持；触发只读保存后两端均保留编辑器、输入和只读提示，无横向溢出或控制台异常。
