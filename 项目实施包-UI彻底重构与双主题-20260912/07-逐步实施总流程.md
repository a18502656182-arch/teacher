# 逐步实施总流程

本文件与tasks/*.md、trackers/tasks.csv配套。每项任务文件都列前置、实操、产物、删除范围和测试。状态初始全部planned。依赖未通过不得宣称后继完成；可以独立准备素材，但不能跳过功能盘点。

## 每个任务的固定操作循环

1. 读任务卡、页面卡、当前进度与Git差异，确认本次负责文件。
2. 打开旧源码与两个端的真实页面，补全遗漏动作。
3. 写下要保留的业务函数/字段及要替换的DOM/CSS。记录当前图仅为反例，不据其限制新设计。
4. 在新组件中实现完整布局与所有状态，用隔离合成数据接业务操作。
5. 运行匹配风险的行为测试；渲染桌面和手机，同尺寸对照参考，登记实际差异。
6. 集中修复本轮问题，再做确认轮。未通过保留needs-fix，不能因为技能轮次限制或上下文不足标通过；后续明确继续任务。
7. 核对新页不依赖旧CSS后接主入口；删旧实现；重新检查受影响的共用页面。
8. 更新任务状态/源码提交/证据位置、CHANGELOG和PROJECT_STATUS。长期选择同步DECISIONS。检查敏感内容并提交推送github/main。

## 里程碑门槛

M0：功能与弹窗账本完整、隔离测试环境可用，源码基线已核对。
M1：共享组件与C1–C6代表构图视觉达标，主题接口可替换且无公开玻璃入口。
M2：首页/学生/作业/考勤/听写所有状态接真业务，在隔离数据上完成保存失败和冲突流程。
M3：其余14模块+家庭子场景+入口/账户/管理员/隐私全部迁移，功能账本无未处置缺口。
M4：旧CSS/DOM退出，静态和浏览器审计识别新结构，全部测试与视觉记录有效。
M5：可审查提交与部署包，本地解压检查，服务器状态单独记录。

## 如何恢复中断

读取progress.json的active_task，再看任务文件和未提交差异。若task写done但证据/提交缺失，回退任务状态为needs-verification，不回退代码。比较基线与当前变更，不能反复重做已通过页面。下一对话先简述已完成/进行中/下一个具体动作，随后执行。

## 工作量安排

不以固定天数承诺完成。先在M0盘点实际弹窗数量，再估计任务规模。单项卡包含多个页面时逐页交付证据，不能用一页截图代表整族。测试和素材成本以真实结果调整；不得为了赶进度把原结构换色算迁移。
